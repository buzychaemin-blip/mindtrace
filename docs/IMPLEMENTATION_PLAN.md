# MindTrace 구현 계획

## 범위와 완료 조건

기존 REA 작업을 보존하고 별도 mindtrace 폴더에 구현한다. 첨부 지시서를 제품 요구사항으로 사용하며, 최우선은 단계 A 실행 가능한 웹 MVP이다.

- [x] React/TypeScript 반응형 웹앱, 데모/빈 개인 로컬 모드 분리 및 온보딩
- [x] 과목 CRUD, 타임스탬프/구간 기반 타이머와 복구·중복 종료 방지
- [x] 10분 플래너 CRUD, 날짜 경계, 할 일 CRUD·우선순위·일정
- [x] 수동 사용 기록 CRUD, 시간대·이유 통계
- [x] 설명 가능한 규칙 코치와 수락·수정·거절 가능한 미션
- [x] 일·주·월 학습 통계/캘린더, 비교 리포트와 결측 제외 웰빙 지표
- [x] 뽀모도로, D-Day, 휴식·취침 자기보고, 테마, 알림 설정
- [x] 개인정보 JSON/CSV 내보내기·삭제, 공개 기본 OFF
- [x] Supabase 선택 어댑터 및 RLS 마이그레이션 작성, 실제 연결은 미검증으로 표시
- [x] 핵심 도메인 테스트 18개와 브라우저 흐름 8개/반응형 검증 통과
- [x] 실행·아키텍처·AI·개인정보·API·시연·제한 문서
- [ ] 실제 Supabase 계정 2개 연결 및 RLS 검증 (프로젝트/인증 설정 필요)
- [ ] 실제 그룹 Realtime 및 Android 단계 (로컬 그룹 시연만 구현)

## 기술 선택

Vite + React + TypeScript 정적 웹앱을 먼저 구현한다. 로컬 저장과 키 없는 규칙 분석을 클라이언트에서 수행하여 심사 데모가 외부 서버에 의존하지 않도록 한다. Next.js/FastAPI의 중복 계층을 만들지 않는다. 온라인 계정은 Supabase 선택 어댑터와 RLS를 사용한다. 온라인 계정과 Android는 실제 인프라/SDK/기기가 없는 경우 완료로 보고하지 않는다. 상세 근거는 ARCHITECTURE.md에 기록한다.

## 단계 순서

1. 도메인 모델·검증·저장과 기본 UI → 단계 A 실행
2. 일주월 통계·비교·루틴 등 실행 가능한 단계 B/C의 로컬 기능
3. 선택 온라인 연결 및 권한 스키마, 실제 미연결 상태 안내
4. 단위/빌드/E2E 점검 후 문서와 시연 환경 제공

Android, 영상 스터디, 웨어러블, 외부 AI API는 본 웹 MVP 이후 과제로 분리한다. 실제 그룹 다중 사용자 공유는 연결 검증 전 완성 기능으로 표시하지 않는다.
