## 도메인 검증 내용

- 타이머 직렬화 복구, 일시정지 제외, 중복 시작·종료, 시각 역행, 진행 과목 삭제 거부
- 뽀모도로 집중/휴식 분리, 지연 감지 시 설정 시간 상한, 완료 단계 재개 거부
- 실제 공부 구간의 자정 분할과 휴식 제외
- 23:50~00:10 계획, 겹침 및 10분 위반 입력 거부
- 과목 보관 후 기록 유지, 잘못된 이름·사용 시간·미래 입력 거부
- 데이터 없음의 무결론/null 점수, 결측 가중치 재정규화
- 사용 기록에 따른 코치 변화, 이전 기간 비교, 과도한 공부 가점 없음
- CSV 수식 입력 무력화, 손상된 중첩 저장 데이터 거부

## E2E 시나리오

1. 타이머 시작→일시정지 완료 확인→새로고침→재개→단일 저장.
2. 자정 계획 생성/수정/삭제와 할 일 완료.
3. 빈 개인 모드→45분 사용 기록→코치 패턴→미션 완료→삭제, 가상 모드 보존.
4. 모든 메뉴 런타임 오류 없음, 데스크톱과 390px 모바일 가로 넘침 없음.
5. 같은 브라우저 두 탭에서 동시에 시작해도 동일 active id 유지.
6. 브라우저 시각 65초 전진 시 1분 뽀모도로 상한/재개 차단/휴식 전환.
7. 가상 그룹 생성/비공개 기본값/체크인/나가기, 다크 모드, 실제 CSV 다운로드 이벤트.
8. 손상된 캐시 자동 덮어쓰기 없음, 명시적 삭제 후 복구.

## 발견하고 수정한 항목

- 초기 localStorage 중심 변경에서 다중 탭 경합 발견 → IndexedDB readwrite 트랜잭션으로 기준 저장소 변경.
- 테스트가 설정 버튼을 nav 내부에서만 찾던 선택자 수정.
- 비동기 일시정지 저장 전 화면 숫자를 읽던 테스트 경합 → 재개 버튼이 나타나 저장 완료한 뒤 비교.
- 뽀모도로 지연 종료/완료 단계 재개를 도메인에서 제한.
- 손상된 저장 데이터는 보존하되 명시적 삭제로 복구 가능하도록 처리.
- 보조 텍스트 색상과 크기 개선.

## 실행하지 않은 검증

실제 Supabase 로그인/메일/다중 계정 RLS, 원격 동시 백업 충돌, Android 빌드·실기기 권한, Safari/iOS, OS 전체 사용량, 실제 다중 사용자 그룹은 미검증/미구현입니다. SQL은 작성했으나 실제 DB에 적용하지 않았습니다. 외부 AI 모델은 사용하지 않습니다. ESLint/전체 접근성 자동 심사는 실행하지 않았으며 TypeScript와 실제 브라우저 흐름으로 확인했습니다.

호스팅 성공 여부는 배포 결과로 별도 확인합니다. 로컬 E2E 결과를 원격 인증/실서비스 검증으로 해석하지 않습니다.
